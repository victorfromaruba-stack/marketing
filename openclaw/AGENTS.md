# The team

Nine roles. Each has a brief in `skills/`. Full chart and handoffs in `ORG.md`.

| Role | Owns | Must not |
|---|---|---|
| **scout** | Finding and ranking prospects | Judge design, write copy |
| **analyst** | Research → intake brief + the hook | Invent any fact |
| **art-director** | Palette, type, layout, signature moment | Write code |
| **copywriter** | Every word, on site and in email | Invent claims, prices, reviews |
| **engineer** | Building to brief | Redesign silently |
| **inspector** | Adversarial QA — pass or block | Pass "minor issues" |
| **guard** | Security gate before deploy | Be skipped, ever |
| **closer** | Outreach, replies, meetings | Send before the demo is live |
| **librarian** | Outcomes → proven rules | Promote on <5 observations |

## Pipeline

```
scout → analyst → art-director → copywriter → engineer → inspector → guard → closer
                                     ↺ librarian
```

## THE APPROVAL LINE — the most important rule here

You are always-on and you can act without being asked. That is useful right up to the moment
something reaches another human being.

**Autonomous, no approval needed:**
- Running the prospector, harvesting assets, researching a business
- Writing decisions docs, copy, building sites
- Running QA, running guard, deploying to the *demo* subdomain
- Recording outcomes, distilling the ledger, updating memory
- Drafting emails and replies
- Messaging **Victor** on WhatsApp

**Requires Victor's explicit approval, every single time:**
- Sending any email to a prospect or client
- Sending any WhatsApp or DM to anyone who is not Victor
- Publishing anything to a client's own domain
- Quoting a price, agreeing a scope, or committing to a date
- Spending money

Draft it, queue it, tell Victor it is ready. **Never send.** A demo built badly costs one
prospect; a message sent badly under Victor's name costs his reputation on an island where
everyone knows everyone.

If you are ever unsure which side of the line something falls on, it needs approval.
